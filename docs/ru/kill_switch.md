# Kill switch (аварийное отключение)

RioNexTunnel может блокировать исходящий интернет, если VPN-туннель или локальный core (xray/sing-box) неожиданно остановился. Это снижает утечки при падении core или обрыве туннеля.

## Режимы

| Режим | Поведение |
|-------|-----------|
| **Off** | Обычное отключение — приложения могут выйти в интернет напрямую, если прокси/VPN упал. |
| **Strict** | Блокировать **весь** исходящий трафик при падении туннеля/core до переподключения или отключения. |
| **Adaptive** | Блокировка по приложениям — **ещё не реализовано**; нужен split tunneling (Agent B). |

Настройка: **Settings → Kill switch**.

## Proxy mode (Linux, Windows, macOS)

На десктопе используется **proxy mode**, не полноценный TUN VPN.

### Strict mode

1. При подключении правила firewall (Linux: iptables/nftables) разрешают только loopback и локальные прокси (`127.0.0.1:1080` SOCKS, `1081` HTTP) с авторизацией.
2. При выходе core системный прокси отключается, исходящий трафик **блокируется** (fail closed).
3. При отключении пользователем все правила снимаются.

### Ограничения

- **Linux**: нужны `iptables` или `nft` с правами (часто root или `CAP_NET_ADMIN`). Без них kill switch не блокирует на уровне ОС.
- **Windows / macOS**: полная интеграция WFP / `pf` пока не поставляется. Strict снимает системный прокси; приложения, игнорирующие прокси, могут подключаться напрямую.
- **Расширение браузера**: защищён трафик через системный HTTP-прокси с авторизацией; прямые сокеты приложений на desktop proxy mode не полностью покрыты.

## TUN mode (Android, iOS)

На мобильных — `VpnService` / `NEPacketTunnelProvider`.

### Strict mode

- **Android**: `setBlocking(true)` — при отключении VPN Android блокирует трафик вне VPN. При падении core туннель остаётся, трафик не проходит.
- **iOS**: `includeAllNetworks` при Strict — блокируются интерфейсы вне VPN при активном туннеле.

### Ограничения

- **iOS**: adaptive per-app — после split tunneling.
- Kill switch на уровне ОС VPN; на desktop proxy mode не заменяет изоляцию каждого приложения.

## Безопасность

- Kill switch не открывает неаутентифицированный SOCKS на `127.0.0.1`.
- Учётные данные сессии стираются при disconnect.
- Strict + auto-reconnect: трафик блокирован до успешного переподключения.
