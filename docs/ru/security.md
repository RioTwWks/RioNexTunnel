# Безопасность

[← Оглавление документации](README.md) · [English](../en/security.md)

## Контекст угроз

В марте 2026 у ряда популярных VPN-клиентов (Hiddify, v2rayNG, Happ и др.) был обнаружен **неаутентифицированный локальный SOCKS5-прокси** (часто порт `7890`, иногда привязка к `0.0.0.0`). Любое локальное приложение могло:

- Узнать реальный IP пользователя
- Использовать туннель VPN без ведома клиента
- Читать или вмешиваться в трафик, который должен оставаться внутри приложения

Этот проект спроектирован так, чтобы быть устойчивым к этому классу проблем.

## Непреложные правила

| Правило | Требование |
|---------|------------|
| Адрес привязки | Только `127.0.0.1` — никогда `0.0.0.0` |
| Аутентификация | Локальные SOCKS5 / HTTP inbound всегда требуют password auth |
| Учётные данные | Случайный логин/пароль на сессию (CSPRNG) |
| Время жизни | Генерация при connect, уничтожение при disconnect |
| Хранение | Никогда не писать credentials на диск и в логи |
| Порт `7890` | Не оставлять неаутентифицированный listener на этом (и любом) порту |

## Точки реализации

- **Dart:** `CredentialService` + `ConfigParser.injectSecureSocksInbound(...)`
- **Desktop:** `proxyOnly: true` убирает VPN-only inbound; добавляет HTTP с auth на `1081` для системного прокси
- **Native (Linux):** канал credentials `secure_vpn/credentials`; env для дочернего процесса; конфиг стирается при stop
- **Браузер:** опциональное расширение отвечает на HTTP `407` — с теми же сессионными credentials (без открытого forwarder)

## Как проверить

1. Подключите VPN в приложении.
2. Probe без учётных данных (должен упасть):

```bash
# Из корня репозитория
./scripts/security_probe.sh 1080
```

3. Опциональная ручная проверка:

```bash
curl --socks5 127.0.0.1:1080 https://api.ipify.org
# Без user:pass → ошибка / туннель не используется
```

4. Автотесты: `secure_vpn_client/test/security_test.dart`, `test/config_parser_test.dart`.

```bash
cd secure_vpn_client
flutter test test/security_test.dart
```

## Что значит «Connected» на desktop

На Linux/Windows/macOS используется **proxy mode**, а не полноценный TUN VPN. Трафик идёт через локальный аутентифицированный прокси только если приложения (или системный прокси + помощник браузера) настроены на него. Это намеренная изоляция — не дыра через сканирование открытого localhost.
