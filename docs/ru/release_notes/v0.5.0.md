**Предыдущий релиз:** [v0.4.2](https://github.com/RioTwWks/RioNexTunnel/releases/tag/v0.4.2)

RioNexTunnel v0.5.0 — крупный релиз: паритет десктопных платформ, стабильность подключения и четыре ключевые функции P1 — **kill switch**, **split tunneling**, **пресеты обхода цензуры** и опциональная интеграция с панелью **RioNexGate**. Базовая модель безопасности не изменилась и усилена автоматическими проверками в CI.

---

## Главное

- **Kill switch (режим Strict)** — блокировка исходящего интернета при неожиданном падении VPN-туннеля или локального ядра. Linux (iptables), Android/iOS (уровень VPN), десктоп — fallback в proxy-режиме.
- **Split tunneling на Android** — белый список (VPN только для выбранных приложений) или чёрный список (обход VPN). Поиск по установленным приложениям. На десктопе — информационный баннер; ограничения iOS задокументированы.
- **Мастер обхода цензуры** — пресеты транспорта (XHTTP+REALITY, WebSocket/gRPC/HTTPUpgrade+TLS, mux), выбор uTLS-отпечатка и пресет **RU sites direct** при импорте или редактировании профиля.
- **Паритет платформ** — плагины Windows и macOS для proxy-режима с SOCKS `127.0.0.1:1080` + HTTP `1081`, канал сессионных credentials, системный прокси. Android/iOS — согласованная передача credentials.
- **Стабильность фундамента** — авто-переподключение с экспоненциальной задержкой, детальные состояния (Connecting / Reconnecting / Error), статистика upload/download и uptime на главном экране.
- **Панель RioNexGate (опционально)** — сопряжение клиента для подписок, синхронизации конфига и статистики. Если панель не настроена, поведение не меняется.

## Безопасность

В v0.5.0 по-прежнему действуют обязательные правила:

| Принцип | Реализация |
|---------|------------|
| Только localhost | SOCKS/HTTP слушают `127.0.0.1` — никогда `0.0.0.0` |
| Обязательная аутентификация | Случайные логин/пароль на каждое подключение |
| Нет открытого порта 7890 | Неаутентифицированный SOCKS отклоняется при валидации |
| Очистка credentials | Сессионные данные и `active_config.json` удаляются при отключении |
| Изоляция split tunnel | Исключённые приложения не могут использовать открытый локальный прокси |

**Новое в v0.5.0:**

- **CI Linux SOCKS security probe** — job `linux-security-probe` запускает `scripts/ci_security_probe_linux.sh` при интеграционных тестах и проверяет, что после connect доступен только аутентифицированный listener.
- **Geo fail-closed** — если в конфиге есть `geosite:` / `geoip:`, но нет geo-ассетов, подключение блокируется с понятной ошибкой (нужно для пресета RU direct и маршрутизации из подписки).
- **Kill switch + reconnect** — в режиме Strict трафик остаётся заблокированным во время попыток переподключения, пока туннель снова не станет рабочим.

Проверка локально после connect:

```bash
./scripts/security_probe.sh 1080
```

См. [security.md](../security.md).

## Новые возможности

### Kill switch — режим Strict ([#53](https://github.com/RioTwWks/RioNexTunnel/pull/53))

Настройка: **Settings → Kill switch**:

| Режим | Статус |
|-------|--------|
| **Off** | По умолчанию — обычное отключение |
| **Strict** | Блокировка всего исходящего трафика при падении ядра/туннеля |
| **Adaptive** | Блокировка по приложениям — **отложено** (нужна интеграция со split tunnel) |

- **Linux:** правила iptables/nftables для loopback и аутентифицированных портов прокси; при падении ядра — drop исходящего.
- **Android:** `VpnService.Builder.setBlocking(true)` — трафик вне VPN блокируется при обрыве туннеля.
- **iOS:** `includeAllNetworks` при включённом Strict.
- **Windows / macOS:** сброс системного прокси + fallback proxy-режима; полная интеграция WFP / `pf` ещё не поставляется.

Документация: [kill_switch.md](../kill_switch.md)

### Split tunneling — маршрутизация по приложениям на Android ([#50](https://github.com/RioTwWks/RioNexTunnel/pull/50))

Настройка: **Settings → Split tunneling**:

| Режим | Поведение |
|-------|-----------|
| **Off** | Все приложения через VPN |
| **VPN only** (белый список) | VPN только для выбранных приложений |
| **Bypass** (чёрный список) | Выбранные приложения идут напрямую |

- Список установленных приложений с поиском и переключателями.
- Само VPN-приложение всегда исключено на нативном уровне.
- После смены списка или режима нужно **переподключиться**.
- Десктоп: баннер об ограничениях proxy-режима на уровне ОС.

Документация: [split_tunneling.md](../split_tunneling.md)

### Обход цензуры — пресеты транспорта и мастер ([#52](https://github.com/RioTwWks/RioNexTunnel/pull/52))

При добавлении или редактировании профиля мастер **Censorship mode** предлагает:

- **Пресеты транспорта** — XHTTP+REALITY (`stream-one`), WebSocket/gRPC/HTTPUpgrade+TLS, plain TLS, mux для мобильных операторов.
- **uTLS fingerprint** — `firefox`, `edge`, `chrome`, `safari`, `random` (по умолчанию **firefox**, если в ссылке нет `fp`).
- **RU sites direct** — `geosite:ru` / `geoip:ru` в direct outbound (нужны geo-ассеты из `scripts/fetch_cores.sh`).
- **Автоопределение** — подсказка транспорта из метаданных подписки/ссылки.
- **ConfigEnhancer** — применение пресетов к JSON xray/sing-box без кастомных форков Xray.

Используется только **официальный Xray-core** — без неподдерживаемых REALITY-форков.

Документация: [censorship_resistance.md](../censorship_resistance.md)

### Панель RioNexGate — опциональный MVP ([#51](https://github.com/RioTwWks/RioNexTunnel/pull/51))

Сопряжение с сервером [RioNexGate](https://github.com/RioTwWks/RioNexGate) для управляемых подписок и статистики. **Полностью опционально** — ручные ссылки и сторонние подписки работают как раньше.

- **Settings → RioNexGate panel** — URL панели, регистрация/вход, ручное обновление.
- **PanelManager** — REST-клиент с таймаутами, повторами, сравнением `config_hash`, офлайн-кэшем.
- **Загрузка статистики** — bytes in/out в очереди при отключении; повторная отправка при восстановлении связи.
- **Карточка статуса** — synced / stale / offline / error (без секретов в UI).

Токен устройства панели отделён от auth транспорта VPN и сессионных SOCKS-credentials.

### Паритет платформ — Windows, macOS, Android, iOS ([#39](https://github.com/RioTwWks/RioNexTunnel/pull/39), [#41](https://github.com/RioTwWks/RioNexTunnel/pull/41))

| Платформа | Что нового |
|-----------|------------|
| **Windows** | Десктопный proxy-плагин, системный прокси WinINet/registry, ядра в `resources/` |
| **macOS** | Порты 1080/1081, канал credentials, HTTP system proxy |
| **Android** | Проба `xray_available`, session creds в `start_with_json`, per-app split tunnel |
| **iOS** | PacketTunnel + миграция на Libbox API для sing-box 1.14, канал credentials, persist/wipe конфига |

Чеклист: [platform_parity_checklist.md](../platform_parity_checklist.md)

## Заметки по платформам

### Linux (эталон — проверено)

- Proxy-режим с GNOME system proxy и расширением для браузера.
- Kill switch Strict через iptables (нужны `CAP_NET_ADMIN` или root).
- Перед первым connect: `./scripts/fetch_cores.sh`.

### Windows

- Proxy-режим: HTTP `127.0.0.1:1081`, SOCKS `127.0.0.1:1080` с сессионной auth.
- **Browser helper пока недоступен** — копируйте credentials с Home/Settings (бэклог P3).

### macOS

- Та же схема портов, что на Linux; credentials в Settings при подключении.
- Kill switch: fallback proxy-режима; полные правила `pf` не поставляются.

### Android

- Полноценный TUN VPN; split tunnel и kill switch на уровне `VpnService`.
- Переподключение после смены split tunnel.

### iOS

- Только sing-box (автовыбор движка); нужен PacketTunnel extension.
- Per-app split tunnel **недоступен** (ограничение Network Extension) — используйте пресеты маршрутизации.
- XHTTP+REALITY может не работать; предпочитайте TCP+REALITY+Vision из подписки.

## Известные ограничения и отложенные задачи

| Пункт | Статус | Примечание |
|-------|--------|------------|
| Kill switch **Adaptive** | Отложено | Блокировка по приложениям; интеграция со split tunnel |
| **Browser helper** на Windows | P3 | На Linux полная реализация; на Windows status возвращает `false` |
| WebSocket-команды RioNexGate | Не в MVP | `refresh_config`, `disconnect`, `switch_server` — в планах |
| Периодическая отправка stats RioNexGate | Частично | Только при disconnect; таймер ~60 с не реализован |
| Полное применение JSON конфига панели | Частично | Импорт subscription URL работает; прямой JSON — в планах |
| Цепочка auto-fallback протоколов | Частично | Есть выбор по latency; упорядоченный fallback транспорта — в планах |
| Per-app split tunnel на iOS | Недоступно | Ограничение Apple NE — пресеты RU direct / домены |
| Полный OS firewall Windows/macOS | Не поставляется | WPF / `pf` для kill switch в proxy-режиме |
| Obfuscation AmneziaWG | Пока нет | В бэклоге P1/P2 |

## Обновление

1. **Десктоп:** выполните `./scripts/fetch_cores.sh` для обновления xray/sing-box и geo-ассетов перед connect с RU direct или geo-правилами.
2. **Android split tunnel / kill switch:** переподключите VPN после смены настроек.
3. **RioNexGate:** опционально — пропустите настройку панели, если используете только ручные ссылки или сторонние подписки.
4. **Безопасность без изменений:** SOCKS на `127.0.0.1` с сессионным паролем; credentials стираются при отключении.
