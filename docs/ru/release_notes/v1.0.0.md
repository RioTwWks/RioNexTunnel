# RioNexTunnel v1.0.0

<p align="right">
  <a href="../../en/release_notes/v1.0.0.md"><img src="https://img.shields.io/badge/lang-English-blue?style=for-the-badge" alt="English version"></a>

**P4 — завершение backlog после v0.9.0.** v1.0.0 — первый major-релиз после P3: интеграция с панелью RioNexGate готова к продакшену, адаптивный kill switch связан с per-app split tunneling на Android, ссылки AmneziaWG парсятся только с официальными ядрами, вторичные экраны полностью локализованы, паритет десктопных платформ (browser helper macOS, CI-сборка Windows) задокументирован. Всё новое поведение **опционально** или добавочное; инварианты безопасности SOCKS и пути connect по умолчанию не изменились.

---

## Основное

- **Панель RioNexGate** — отправка статистики каждые 60 с при подключении, плановая синхронизация конфига, connect по полному JSON, защищённое хранение device token, руководство по сопряжению ([#91](https://github.com/RioTwWks/RioNexTunnel/pull/91)).
- **Адаптивный kill switch** — блокировка per-app на Android TUN с интеграцией split tunneling; ограничения десктопа задокументированы ([#88](https://github.com/RioTwWks/RioNexTunnel/pull/88)).
- **AmneziaWG** — парсинг ссылок `awg://`, outbound JSON для sing-box, порядок fallback в цензуроустойчивости; connect **fail-closed** до поддержки в официальном ядре ([#90](https://github.com/RioTwWks/RioNexTunnel/pull/90)).
- **Полная локализация** — вторичные экраны и виджеты перенесены в ARB (~120 новых ключей) ([#92](https://github.com/RioTwWks/RioNexTunnel/pull/92)).
- **Укрепление платформ** — browser helper macOS, CI-задача `flutter build windows`, чеклист E2E-паритета ([#89](https://github.com/RioTwWks/RioNexTunnel/pull/89)).
- **Исправление сборки Windows** — путь CMake install для native messaging host при MSVC multi-config ([#86](https://github.com/RioTwWks/RioNexTunnel/pull/86)).
- **План распределения P4** — разбивка работ агентов и порядок merge ([#87](https://github.com/RioTwWks/RioNexTunnel/pull/87)).

## Панель RioNexGate

Закрыты отложенные пункты roadmap панели из P1: фоновая статистика, плановая синхронизация, применение полного конфига и пользовательская документация по сопряжению.

### Периодическая отправка статистики

При подключённом VPN и активной панели:

- Отправка статистики каждые **60 секунд** через `Timer.periodic` в `panel_providers.dart`
- Финальная отправка при отключении и при ручном обновлении
- В офлайне статистика ставится в очередь и отправляется при восстановлении связи

### Плановая синхронизация конфига

| Параметр | По умолчанию | Варианты |
|----------|--------------|----------|
| Интервал синхронизации | **15 мин** | 15 / 30 / 60 / 120 мин |
| Пропуск без изменений | Да | По `config_hash` — без перезаписи идентичного конфига |

Ручное **Обновление** и WebSocket `refresh_config` работают параллельно с расписанием.

### Connect по полному JSON

Если панель отдаёт полный JSON-объект `config`, RioNexTunnel использует кэшированный/синхронизированный JSON для профиля **RioNexGate** при connect. При отсутствии кэша — прежний пайплайн URL подписки.

### Защищённый device token

- `device_token` хранится в **flutter_secure_storage** (Android/iOS; best-effort на десктопе)
- Стирается при **Сбросе сопряжения** вместе с кэшем конфига и очередью статистики
- Не логируется и не попадает в payload статистики

### Руководство по сопряжению

Новая двуязычная документация описывает добавочную модель интеграции:

- Ручные профили сохраняются при сопряжении и сбросе регистрации панели
- Пошаговое сопряжение из **Настройки → Панель RioNexGate**

См. [panel_pairing.md](../panel_pairing.md) и [rionexgate_testing.md](../rionexgate_testing.md).

## Адаптивный kill switch

**Настройки → Advanced → Kill switch → Adaptive** полностью включён (больше не заглушка).

### Поведение

| Режим | При падении ядра/туннеля |
|-------|--------------------------|
| **Strict** | Блокировка всего исходящего трафика до переподключения или disconnect |
| **Adaptive** | Блокировка только приложений **вне** allow list split tunneling (whitelist) или только из block list (blacklist) — по возможностям платформы |
| **Off** | Обычный disconnect; приложения могут выйти в интернет напрямую |

Адаптивный режим читает per-app список из **Split tunneling** (`per_app_proxy_provider`).

### Поддержка по платформам

| Платформа | Адаптивный kill switch |
|-----------|------------------------|
| **Android (TUN)** | **Поддерживается** — per-app правила firewall через `VpnService` при падении ядра |
| **iOS** | Недоступен — per-app split tunneling на iOS пока не поддерживается |
| **Linux / Windows / macOS (proxy)** | Деградирует в **Strict** — нет per-app блокировки на уровне ОС в proxy mode; UI показывает предупреждение |

Сначала настройте split tunneling в **Настройки → Advanced → Split tunneling** (режим VPN на Android).

См. [kill_switch.md](../kill_switch.md) и [split_tunneling.md](../split_tunneling.md).

## AmneziaWG (`awg://`)

AmneziaWG (AWG) добавляет параметры обфускации DPI поверх WireGuard. RioNexTunnel теперь парсит и классифицирует AWG-узлы в стеке цензуроустойчивости.

### Поддержка ссылок и подписок

- Share-ссылки `awg://` (и `wg://` / `wireguard://` при наличии AWG query-параметров)
- JSON подписок sing-box с AWG-полями на outbound `type: wireguard`
- Порядок fallback-проб включает AmneziaWG при наличии в подписке

### Только официальные ядра — fail closed

Упакованный [SagerNet/sing-box](https://github.com/SagerNet/sing-box) из `scripts/fetch_cores.sh` **ещё не** реализует обфускацию AWG. Клиент:

- Генерирует валидный AWG outbound JSON для подписок и импорта
- **Отказывается от connect** с понятной ошибкой до появления AWG в upstream sing-box
- **Не** поставляет неподдерживаемые форки AWG-ядер

AWG-профили требуют движок **sing-box**. MTU ограничен **1280** для AWG-узлов.

См. [censorship_resistance.md](../censorship_resistance.md#amneziawg).

## Укрепление платформ

### Browser helper macOS

Паритет native messaging с Linux и Windows:

- `get_browser_helper_status` отражает реальное состояние установки при наличии host
- Host копируется в `~/Library/Application Support/V2rayBox/working/native_host/` при первом `setup()`
- Манифесты для Chrome, Chromium, Edge и Firefox

См. [macos_setup.md](../macos_setup.md) и [browser_extension.md](../browser_extension.md).

### Исправление сборки Windows (#86)

`flutter build windows --release` больше не падает на шаге CMake **INSTALL**. Путь к бинарнику native messaging host использует `$<TARGET_FILE:secure_vpn_native_host>` для выходных каталогов MSVC multi-config.

### CI-задача сборки Windows

`.github/workflows/ci.yml` включает задачу `windows-build` на `windows-latest` с `flutter build windows --release` на каждый PR и push в `main`.

### Чеклист E2E-паритета

[platform_parity_checklist.md](../platform_parity_checklist.md) дополнен:

- Шаблоном sign-off E2E (дата, тестер, engine × profile, security probe, browser helper)
- Таблицей путей browser helper macOS
- Примечанием о CI Windows и smoke-шагами по платформам

E2E на устройстве остаётся **ручным** — обновляйте таблицу статуса в [README](../README.md#e2e-device-verification) при sign-off платформы.

## Безопасность

Базовые инварианты v1.0.0 **не изменились**:

| Принцип | Реализация |
|---------|------------|
| Только localhost | SOCKS/HTTP на `127.0.0.1` — никогда `0.0.0.0` |
| Обязательная auth | Пароль на сессию на каждом локальном прокси |
| Нет порта 7890 | Неаутентифицированный SOCKS отклоняется в `validateSecure()` |
| Жизненный цикл credentials | Стираются при disconnect; удаляется `active_config.json` |
| Без логирования секретов | Токены панели, пароли SOCKS и URL конфигов не логируются на уровне INFO |

Новые поверхности (синхронизация панели, адаптивный kill switch, импорт AWG) следуют тем же правилам:

- `device_token` панели — только для API auth, отдельно от транспортных credentials
- Адаптивный kill switch не открывает неаутентифицированный localhost SOCKS
- AWG connect блокируется, а не переходит на неофициальное ядро

## Обновление

Функции P4 **добавочные и в основном опциональные**. Миграция для текущих пользователей не требуется.

1. **Текущие пользователи** — профили, подписки, мультихоп, DNS, маршрутизация и pinning работают как в v0.9.0.
2. **RioNexGate** — опционально в **Настройки → Панель RioNexGate**; ручные профили без изменений.
3. **Адаптивный kill switch** — опционально; настройте split tunneling на Android перед включением Adaptive.
4. **AmneziaWG** — импорт `awg://` доступен; connect завершится ошибкой с документированным сообщением до появления AWG в sing-box.
5. **Локализация** — вторичные экраны следуют **Настройки → Внешний вид → Язык**, как остальное приложение.
6. **macOS** — установите расширение браузера и проверьте карточку browser helper после обновления.
7. **Windows** — release-сборки с v0.9.0 включают исправление CMake; ручных шагов не требуется.

## Известные ограничения

- **Linux TUN split tunnel** — отложено; десктоп использует только proxy mode. См. [split_tunneling.md](../split_tunneling.md).
- **Поддержка ядра AmneziaWG** — outbound JSON и порядок fallback работают; connect заблокирован до реализации AWG-обфускации в официальном sing-box.
- **Адаптивный kill switch на iOS** — недоступен; per-app split tunneling на iOS пока не поддерживается.
- **Адаптивный режим на десктопе** — деградирует в Strict; нет per-app firewall ОС в proxy mode.
- **Публикация в store** — пакет submission готов в `extensions/secure-vpn-proxy-auth/store/`; ссылки Chrome Web Store / Firefox AMO требуют ручной публикации и модерации.
- **E2E на устройстве** — чеклист паритета задокументирован; sign-off на физических устройствах остаётся ручным (адаптивный kill switch Android, browser helper macOS, туннель iOS).
