# RioNexTunnel v0.8.0

<p align="right">
  <a href="../../en/release_notes/v0.8.0.md"><img src="https://img.shields.io/badge/lang-English-blue?style=for-the-badge" alt="English version"></a>
</p>

**P2 — расширенная безопасность и маршрутизация.** В этом выпуске: мультихоп-цепочки VPN, расширенный DNS, визуальный редактор правил маршрутизации и опциональный pinning сертификата подписки. Все новые функции **включаются вручную**; поведение connect по умолчанию и инварианты безопасности не меняются.

---

## Главное

- **Мультихоп (Double VPN)** — последовательная цепочка из двух и более серверов подписки ([#75](https://github.com/RioTwWks/RioNexTunnel/pull/75)).
- **Расширенный DNS** — DoH/DoT, свои резолверы, защита от утечки в TUN и тест утечки в приложении ([#74](https://github.com/RioTwWks/RioNexTunnel/pull/74)).
- **Пользовательские правила маршрутизации** — визуальный редактор, пресеты, импорт/экспорт JSON, слияние с маршрутизацией подписки ([#73](https://github.com/RioTwWks/RioNexTunnel/pull/73)).
- **Certificate pinning** — опциональный SPKI pinning для URL подписки ([#72](https://github.com/RioTwWks/RioNexTunnel/pull/72)).
- **План распределения P2** — документация по агентам и координации ([#71](https://github.com/RioTwWks/RioNexTunnel/pull/71)).

## Мультихоп (Double VPN)

Трафик проходит **через два и более VPN-сервера подряд** для дополнительного слоя маршрутизации.

### Как пользоваться

1. Профиль **подписки** с минимум двумя серверами.
2. На **главном экране** выберите **входной сервер**.
3. Включите **Multihop (Double VPN)** и отметьте дополнительные hop.
4. Подключайтесь как обычно.

### Поведение движков

| Движок | Механизм |
|--------|----------|
| Xray-core | Цепочки `proxySettings` между outbounds |
| sing-box | `detour` на outbounds |

Локальный аутентифицированный SOCKS/HTTP на `127.0.0.1` **не меняется** — мультихоп не открывает дополнительные порты.

### Задержка и анонимность

Каждый hop добавляет RTT. Мультихоп обменивает скорость на прохождение через несколько узлов. Используйте, когда нужен дополнительный слой, а не для повседневного интернета.

### Ограничения

- Только профили подписки (не одиночные share-ссылки).
- Минимум два **разных** сервера.
- WireGuard, SSH и Hysteria нельзя использовать как промежуточный hop (как exit на sing-box — возможно).

См. [multihop.md](../multihop.md).

## Расширенный DNS

**Настройки → Advanced DNS** (мобильный VPN/TUN).

### Режимы

| Режим | Описание |
|-------|----------|
| **По умолчанию** | UDP-резолверы `8.8.8.8` и `1.1.1.1` |
| **Свой** | Пользовательские UDP, DoH или DoT upstream |
| **Шифрованный** | Пресеты DoH/DoT (Cloudflare, Google, Quad9) через detour proxy |

### Защита от утечки

При включении (по умолчанию на мобильном TUN) DNS-запросы направляются в туннель через правила `hijack-dns`. На iOS системные DNS-серверы передаются через `flutter.dns_system_servers`.

### Тест утечки DNS

Нажмите **DNS leak test** при активном подключении. Проба выполняет DNS-запрос через Cloudflare и сообщает, прошла ли резолюция, вероятно, через туннель. Данные подписки при тесте не отправляются.

### Desktop proxy

Linux, Windows и macOS работают в **режиме proxy** (`VpnMode.proxy`). Инъекция DNS **пропускается** при `proxyOnly: true` — приложение не перехватывает системный DNS на десктопе. Настройте DNS в ОС или браузере; полный контроль DNS — в TUN-режиме на мобильных.

См. [dns.md](../dns.md).

## Пользовательские правила маршрутизации

Пользовательские правила (домен, IP/CIDR, geosite, geoip) **добавляются перед** маршрутизацией подписки — правила провайдера не заменяются.

**Настройки → Цензуроустойчивость → Пользовательские правила**

### Визуальный редактор

- Добавление, включение/отключение и упорядочивание правил на экране редактора.
- Типы: domain, IP/CIDR, geosite, geoip.
- Действия: proxy, direct, block.

### Пресеты

| Пресет | Поведение |
|--------|-----------|
| **RU direct / rest proxy** | `geosite:ru` и `geoip:ru` → direct; остальной трафик по подписке |
| **Blocked sites only** | Пример блокировки рекламных доменов |

### Импорт / экспорт

Копирование и вставка правил в формате JSON из панели редактора. Правила сохраняются локально через `RoutingRulesService`.

### Слияние с подпиской

`RoutingConfigBuilder.mergeUserRulesIntoConfig()` добавляет включённые правила в начало `routing.rules` для Xray и sing-box. Geo-правила требуют `geoip.dat` / `geosite.dat` — на Xray connect завершается с ошибкой при отсутствии файлов (fail closed).

См. [routing_rules.md](../routing_rules.md).

## Pinning сертификата (опционально)

**Настройки → Advanced security → Subscription certificate pinning (SPKI)**

| Поведение | Детали |
|-----------|--------|
| По умолчанию | Pinning **выключен** — сторонние подписки работают как раньше |
| Область | Только HTTP fetch подписки (`ConfigParser.fetchSubscriptionBody`) |
| Формат pin | `sha256/<base64 SHA-256 SubjectPublicKeyInfo>` |
| Сопоставление хоста | Pin по hostname подписки (без учёта регистра) |
| Проверка | При включении — только хосты с сохранёнными pin; остальные — обычный TLS |
| Panel API | HTTP RioNexGate **не** pin-ится (отдельный код) |

Pin и учётные данные не попадают в логи. Pinning не поддерживается в web-сборках.

См. [security.md](../security.md#pinning-сертификата-подписки-опционально).

## Безопасность

Базовые инварианты v0.8.0 **не изменились**:

| Принцип | Реализация |
|---------|------------|
| Только localhost | SOCKS/HTTP на `127.0.0.1` — никогда `0.0.0.0` |
| Обязательная auth | Пароль на сессию на каждом локальном прокси |
| Нет порта 7890 | Неаутентифицированный SOCKS отклоняется в `validateSecure()` |
| Жизненный цикл credentials | Стираются при disconnect; удаляется `active_config.json` |
| Без логирования секретов | Учётные данные hop, SOCKS и pin не попадают в логи |

Мультихоп добавляет outbound-цепочки, но не ослабляет secure inbound injection. Certificate pinning — **дополнительная** проверка только для opted-in хостов подписки.

Проверка после connect:

```bash
./scripts/security_probe.sh 1080
```

## Обновление

Все функции P2 **опциональны**. Миграция для текущих пользователей не требуется.

1. **Текущие пользователи** — подписки, share-ссылки и синхронизация RioNexGate работают как раньше.
2. **Мультихоп** — включите на главном экране после выбора подписки с двумя и более серверами.
3. **Расширенный DNS** — в настройках; по умолчанию как раньше (Google/Cloudflare UDP).
4. **Правила маршрутизации** — изначально пусты; примените пресет или добавьте правила вручную.
5. **Certificate pinning** — выключен, пока не включите и не сохраните pin для каждого хоста подписки.
6. **Десктоп** — в настройках DNS показано предупреждение о proxy-режиме; системный DNS приложением не управляется.

---

## Известные ограничения

- **DNS на desktop proxy** — расширенный DNS и защита от утечки только для мобильного TUN/VPN. На десктопе в proxy-режиме системный DNS не перехватывается.
- **Задержка мультихопа** — каждый hop добавляет RTT; ожидайте заметно больший ping и медленнее загрузку страниц.
- **Область мультихопа** — только подписки; WireGuard/SSH/Hysteria нельзя как промежуточный hop.
- **Ротация pinning** — при смене TLS-сертификата панели (например, Let's Encrypt) обновите SPKI pin, иначе обновление подписки завершится ошибкой mismatch.
- **Geo-правила** — пресеты geosite/geoip требуют geo-ассетов; на Xray connect fail closed при отсутствии файлов.
- **Web-сборки** — certificate pinning не поддерживается.
