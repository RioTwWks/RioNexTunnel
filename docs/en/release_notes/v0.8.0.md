**P2 — Advanced security & routing.** This release adds multihop VPN chains, advanced DNS controls, a visual routing rule editor, and optional subscription certificate pinning. All new features are **opt-in**; existing connect flows and security invariants are unchanged.

- **Custom routing rules** — visual editor, presets, import/export JSON, merged with subscription routing ([#73](https://github.com/RioTwWks/RioNexTunnel/pull/73)).
- **Certificate pinning** — opt-in SPKI pinning for subscription fetch URLs ([#72](https://github.com/RioTwWks/RioNexTunnel/pull/72)).
- **P2 distribution plan** — agent work breakdown and coordination docs ([#71](https://github.com/RioTwWks/RioNexTunnel/pull/71)).

## Multihop (Double VPN)

Route traffic through **two or more VPN servers in sequence** for an extra routing layer.

### How to use

1. Use a **subscription profile** with at least two servers.
2. On **Home**, pick the **entry server**.
3. Enable **Multihop (Double VPN)** and select additional hops.
4. Connect as usual.

### Engine behavior

| Engine | Mechanism |
|--------|-----------|
| Xray-core | `proxySettings` chains between outbounds |
| sing-box | `detour` on outbounds |

The local authenticated SOCKS/HTTP proxy on `127.0.0.1` is **unchanged** — multihop does not open extra listen ports.

### Latency vs anonymity

Each hop adds round-trip time. Multihop trades speed for routing through multiple nodes. Use it when you need that extra layer, not for everyday browsing.

### Limitations

- Subscription profiles only (not single share links).
- At least two **distinct** servers required.
- WireGuard, SSH, and Hysteria cannot be intermediate hops (may work as exit on sing-box).

See [multihop.md](../multihop.md).

## Advanced DNS

**Settings → Advanced DNS** (mobile VPN/TUN mode).

### Modes

| Mode | Description |
|------|-------------|
| **Default** | UDP resolvers `8.8.8.8` and `1.1.1.1` |
| **Custom** | User-defined UDP, DoH, or DoT upstreams |
| **Encrypted** | DoH/DoT presets (Cloudflare, Google, Quad9) routed through the proxy detour |

### Leak protection

When enabled (default on mobile TUN), DNS queries are routed through the tunnel via `hijack-dns` routing rules. On iOS, system DNS servers are passed through `flutter.dns_system_servers`.

### DNS leak test

Tap **DNS leak test** while connected. The probe resolves a Cloudflare DNS query and reports whether resolution likely went through the tunnel. No subscription data is sent during the test.

### Desktop proxy disclaimer

Linux, Windows, and macOS run in **proxy mode** (`VpnMode.proxy`). Advanced DNS injection is **skipped** when `proxyOnly: true` — the app does not intercept system DNS on desktop. Configure DNS in the OS or browser, or use TUN mode on mobile for full DNS control.

See [dns.md](../dns.md).

## Custom routing rules

User-defined rules (domain, IP/CIDR, geosite, geoip) are **prepended before** subscription routing — they do not replace provider rules.

**Settings → Censorship resistance → Custom routing rules**

### Visual editor

- Add, enable/disable, and reorder rules in the routing editor screen.
- Rule types: domain, IP/CIDR, geosite, geoip.
- Outbound actions: proxy, direct, block.

### Presets

| Preset | Behavior |
|--------|----------|
| **RU direct / rest proxy** | `geosite:ru` and `geoip:ru` → direct; other traffic follows subscription routing |
| **Blocked sites only** | Example ad-domain block rules |

### Import / export

Copy or paste rules as JSON from the editor toolbar. Rules persist locally via `RoutingRulesService`.

### Merge with subscription

`RoutingConfigBuilder.mergeUserRulesIntoConfig()` prepends enabled user rules to the existing `routing.rules` array for both Xray and sing-box. Geo rules require `geoip.dat` / `geosite.dat` — Xray fails closed if assets are missing.

See [routing_rules.md](../routing_rules.md).

## Certificate pinning (optional)

**Settings → Advanced security → Subscription certificate pinning (SPKI)**

| Behavior | Detail |
|----------|--------|
| Default | Pinning **off** — third-party subscriptions keep working |
| Scope | Subscription HTTP fetch only (`ConfigParser.fetchSubscriptionBody`) |
| Pin format | `sha256/<base64 SHA-256 of SubjectPublicKeyInfo>` |
| Host matching | Pins stored per subscription hostname (case-insensitive) |
| Enforcement | When enabled, only hosts with saved pins are checked; other hosts use normal TLS |
| Panel API | RioNexGate panel HTTP is **not** pinned (separate code path) |

Pins and credentials are never written to logs. Pinning is not supported on web builds.

See [security.md](../security.md#subscription-certificate-pinning-optional).

## Security

Core invariants in v0.8.0 are **unchanged**:

| Principle | Implementation |
|-----------|----------------|
| Localhost only | SOCKS/HTTP on `127.0.0.1` — never `0.0.0.0` |
| Mandatory auth | Per-session password on every local proxy |
| No port 7890 | Unauthenticated SOCKS rejected in `validateSecure()` |
| Credential lifecycle | Wiped on disconnect; `active_config.json` removed |
| No secret logging | Hop credentials, SOCKS passwords, and pins never logged |

Multihop adds outbound chains but does not weaken secure inbound injection. Certificate pinning is an **additional** check for opted-in subscription hosts only.

Verify after connect:

```bash
./scripts/security_probe.sh 1080
```

## Upgrade notes

All P2 features are **opt-in**. No migration steps are required for existing users.

1. **Current users** — subscriptions, share links, and RioNexGate panel sync work as before.
2. **Multihop** — enable on Home after selecting a subscription with two or more servers.
3. **Advanced DNS** — configure under Settings; defaults match prior behavior (Google/Cloudflare UDP).
4. **Custom routing** — rules start empty; apply a preset or add rules manually.
5. **Certificate pinning** — remains off until you enable it and save pins per subscription host.
6. **Desktop** — DNS settings show a proxy-mode disclaimer; system DNS is not managed by the app.

---

## Known limitations

- **Desktop proxy DNS** — Advanced DNS and leak protection apply to mobile TUN/VPN mode only. Desktop proxy mode does not intercept system DNS.
- **Multihop latency** — each hop adds RTT; expect noticeably higher ping and slower page loads.
- **Multihop scope** — subscription profiles only; WireGuard/SSH/Hysteria cannot be intermediate hops.
- **Pinning rotation** — when a panel rotates TLS certificates (e.g. Let's Encrypt renewal), update the SPKI pin or subscription refresh will fail with a pin mismatch error.
- **Geo rules** — geosite/geoip presets require geo assets; Xray connect fails closed if files are missing.
- **Web builds** — certificate pinning is not supported.
