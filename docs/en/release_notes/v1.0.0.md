## RioNexGate panel

Closes deferred panel roadmap items from P1: background stats, scheduled sync, full config apply, and end-user pairing docs.

### Periodic stats upload

While VPN is connected and the panel is active:

- Stats flush every **60 seconds** via `Timer.periodic` in `panel_providers.dart`
- Final flush on disconnect and on manual refresh
- Offline stats are queued and replayed when the panel is reachable

### Scheduled config sync

| Setting | Default | Options |
|---------|---------|---------|
| Sync interval | **15 min** | 15 / 30 / 60 / 120 min |
| Skip unchanged | Yes | Uses `config_hash` to avoid rewriting identical configs |

Manual **Refresh** and WebSocket `refresh_config` still work alongside the schedule.

### Full JSON connect

When the panel provides a full `config` JSON object, RioNexTunnel uses the cached/synced JSON for the **RioNexGate** profile on connect. If no cached JSON exists, the subscription URL pipeline is unchanged.

### Secure device token

- `device_token` stored in **flutter_secure_storage** (Android/iOS; best-effort on desktop)
- Wiped on **Clear registration** along with cached panel config and stats queue
- Never logged or included in stats payloads

### Pairing guide

New bilingual docs describe the additive integration model:

- Manual profiles are preserved when pairing or clearing panel registration
- Step-by-step pairing from **Settings → RioNexGate panel**

See [panel_pairing.md](../panel_pairing.md) and [rionexgate_testing.md](../rionexgate_testing.md).

## Adaptive kill switch

**Settings → Advanced → Kill switch → Adaptive** is now fully enabled (no longer a stub).

### Behavior

| Mode | When core/tunnel drops |
|------|------------------------|
| **Strict** | Block all outbound traffic until reconnect or disconnect |
| **Adaptive** | Block only apps **outside** the split-tunnel allow list (whitelist) or only apps in the block list (blacklist) — per platform capabilities |
| **Off** | Normal disconnect; apps may use direct internet |

Adaptive mode reads the per-app list from **Split tunneling** (`per_app_proxy_provider`).

### Platform support

| Platform | Adaptive kill switch |
|----------|----------------------|
| **Android (TUN)** | **Supported** — per-app firewall rules via `VpnService` when core dies |
| **iOS** | Not available — per-app split tunneling not yet supported on iOS |
| **Linux / Windows / macOS (proxy)** | Degrades to **Strict** — no OS-level per-app blocking in proxy mode; UI shows limitation banner |

Configure split tunneling first under **Settings → Advanced → Split tunneling** (Android VPN mode).

See [kill_switch.md](../kill_switch.md) and [split_tunneling.md](../split_tunneling.md).

## AmneziaWG (`awg://`)

AmneziaWG (AWG) adds DPI obfuscation parameters on top of WireGuard. RioNexTunnel now parses and classifies AWG nodes in the censorship resistance stack.

### Link and subscription support

- `awg://` share links (and `wg://` / `wireguard://` when AWG query params are present)
- sing-box subscription JSON with AWG fields on `type: wireguard` outbounds
- Fallback probe order includes AmneziaWG when present in subscription

### Official cores only — fail closed

The bundled [SagerNet/sing-box](https://github.com/SagerNet/sing-box) from `scripts/fetch_cores.sh` does **not** yet implement AWG obfuscation. The client:

- Generates valid AWG outbound JSON for subscriptions and import
- **Refuses connect** with a clear error until upstream sing-box adds AWG support
- Does **not** ship unmaintained AWG core forks

AWG profiles require the **sing-box** engine. MTU is clamped to **1280** for AWG nodes.

See [censorship_resistance.md](../censorship_resistance.md#amneziawg).

## Platform hardening

### macOS browser helper

Native messaging host parity with Linux and Windows:

- `get_browser_helper_status` reports real install state when host is present
- Host copied to `~/Library/Application Support/V2rayBox/working/native_host/` on first `setup()`
- Manifests for Chrome, Chromium, Edge, and Firefox

See [macos_setup.md](../macos_setup.md) and [browser_extension.md](../browser_extension.md).

### Windows build fix (#86)

`flutter build windows --release` no longer fails at the CMake **INSTALL** step. The native messaging host binary path uses `$<TARGET_FILE:secure_vpn_native_host>` for MSVC multi-config output directories.

### Windows CI build job

`.github/workflows/ci.yml` includes a `windows-build` job on `windows-latest` that runs `flutter build windows --release` on every PR and push to `main`.

### E2E parity checklist

[platform_parity_checklist.md](../platform_parity_checklist.md) adds:

- E2E sign-off template (date, tester, engine × profile, security probe, browser helper)
- macOS browser helper paths table
- Windows CI note and per-platform smoke steps

Device E2E remains **manual** — update the status table in [README](../README.md#e2e-device-verification) when signing off a platform.

## Security

Core invariants in v1.0.0 are **unchanged**:

| Principle | Implementation |
|-----------|----------------|
| Localhost only | SOCKS/HTTP on `127.0.0.1` — never `0.0.0.0` |
| Mandatory auth | Per-session password on every local proxy |
| No port 7890 | Unauthenticated SOCKS rejected in `validateSecure()` |
| Credential lifecycle | Wiped on disconnect; `active_config.json` removed |
| No secret logging | Panel tokens, SOCKS passwords, and config URLs never logged at INFO |

New surfaces (panel sync, adaptive kill switch, AWG import) follow the same rules:

- Panel `device_token` is API auth only — separate from transport credentials
- Adaptive kill switch never opens unauthenticated localhost SOCKS
- AWG connect is blocked rather than falling back to an unofficial core

## Upgrade notes

P4 features are **additive and mostly opt-in**. No migration steps are required for existing users.

1. **Current users** — profiles, subscriptions, multihop, DNS, routing, and pinning work as in v0.9.0.
2. **RioNexGate** — opt-in under **Settings → RioNexGate panel**; manual profiles unchanged.
3. **Adaptive kill switch** — optional; configure split tunneling on Android before enabling Adaptive.
4. **AmneziaWG** — import `awg://` links now; connect will fail with a documented message until sing-box adds AWG.
5. **Localization** — secondary screens now follow **Settings → Appearance → Language** like the rest of the app.
6. **macOS** — install the browser extension and verify the browser helper card after upgrade.
7. **Windows** — release builds from v0.9.0 onward include the CMake fix; no manual steps required.

## Known limitations

- **Linux TUN split tunnel** — deferred; desktop uses proxy mode only. Documented in [split_tunneling.md](../split_tunneling.md).
- **AmneziaWG core support** — outbound JSON and fallback ordering work; connect blocked until official sing-box implements AWG obfuscation.
- **iOS adaptive kill switch** — not available; per-app split tunneling not supported on iOS yet.
- **Desktop adaptive mode** — degrades to Strict; no per-app OS firewall in proxy mode.
- **Extension store publish** — submission package ready under `extensions/secure-vpn-proxy-auth/store/`; Chrome Web Store / Firefox AMO links require manual publish and review.
- **Device E2E** — platform parity checklist is documented; physical device sign-off remains manual (Android adaptive kill switch, macOS browser helper, iOS tunnel).
