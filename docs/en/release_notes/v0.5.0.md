**Release date:** 2026-09-02  
**Previous release:** [v0.4.2](https://github.com/RioTwWks/RioNexTunnel/releases/tag/v0.4.2)

RioNexTunnel v0.5.0 is a major milestone: cross-platform desktop proxy parity, connection stability improvements, and four P1 differentiators — **kill switch**, **split tunneling**, **censorship resistance presets**, and optional **RioNexGate panel** pairing. Security fundamentals are unchanged and reinforced with automated CI checks.

---

## Highlights

- **Kill switch (Strict mode)** — block outbound internet when the VPN tunnel or local core stops unexpectedly. Available on Linux (iptables), Android/iOS (VPN layer), and desktop proxy-mode fallback.
- **Split tunneling on Android** — whitelist (VPN only selected apps) or blacklist (bypass selected apps) with a searchable installed-app picker. Desktop shows an informational banner; iOS limitations documented.
- **Censorship resistance wizard** — transport presets (XHTTP+REALITY, WebSocket/gRPC/HTTPUpgrade+TLS, mux), uTLS fingerprint picker, and **RU sites direct** routing preset when importing or editing profiles.
- **Platform parity** — Windows and macOS desktop proxy plugins with `127.0.0.1:1080` SOCKS + `1081` HTTP, session credentials channel, and system proxy integration. Android/iOS credential plumbing aligned.
- **Foundation stability** — auto-reconnect with exponential backoff, detailed connection states (Connecting / Reconnecting / Error), live upload/download stats and uptime on Home.
- **RioNexGate panel (optional)** — opt-in client pairing for subscriptions, config sync, and stats upload. If you never configure a panel, behavior is unchanged.

## Security

These rules remain non-negotiable in v0.5.0:

| Principle | Implementation |
|-----------|----------------|
| Localhost only | SOCKS/HTTP inbounds bind to `127.0.0.1` — never `0.0.0.0` |
| Mandatory auth | Per-session random username/password on every connect |
| No open port 7890 | Unauthenticated SOCKS is rejected at config validation |
| Credential wipe | Session credentials and `active_config.json` cleared on disconnect |
| Split tunnel isolation | Excluded apps cannot reach an unauthenticated local proxy |

**New in v0.5.0:**

- **CI Linux SOCKS security probe** — the `linux-security-probe` job runs `scripts/ci_security_probe_linux.sh` during integration tests to verify authenticated-only listeners after connect.
- **Geo fail-closed** — if a config references `geosite:` / `geoip:` rules but geo assets are missing, connect is blocked with a clear error (required for RU direct preset and subscription routing).
- **Kill switch + reconnect** — traffic stays blocked during reconnect attempts until the tunnel is healthy again (Strict mode).

Verify locally after connect:

```bash
./scripts/security_probe.sh 1080
```

See [security.md](../security.md).

## New features

### Kill switch — Strict mode ([#53](https://github.com/RioTwWks/RioNexTunnel/pull/53))

Configure in **Settings → Kill switch**:

| Mode | Status |
|------|--------|
| **Off** | Default — normal disconnect behavior |
| **Strict** | Block all outbound traffic when core/tunnel drops |
| **Adaptive** | Per-app blocking — **deferred** (requires split-tunnel integration) |

- **Linux:** iptables/nftables rules allow loopback and authenticated proxy ports; outbound dropped on core crash.
- **Android:** `VpnService.Builder.setBlocking(true)` — non-VPN traffic blocked when tunnel is down.
- **iOS:** `includeAllNetworks` when Strict is enabled.
- **Windows / macOS:** system proxy teardown + proxy-mode fallback; full WFP / `pf` firewall integration not yet shipped.

Docs: [kill_switch.md](../kill_switch.md)

### Split tunneling — Android per-app routing ([#50](https://github.com/RioTwWks/RioNexTunnel/pull/50))

Configure in **Settings → Split tunneling**:

| Mode | Behavior |
|------|----------|
| **Off** | All apps use VPN |
| **VPN only** (whitelist) | Only selected apps use VPN |
| **Bypass** (blacklist) | Selected apps connect directly |

- Searchable installed-app list with toggles.
- VPN app always excluded at the native layer.
- **Reconnect required** after changing app list or mode.
- Desktop: informational banner explains OS-level limits in proxy mode.

Docs: [split_tunneling.md](../split_tunneling.md)

### Censorship resistance — transport presets & wizard ([#52](https://github.com/RioTwWks/RioNexTunnel/pull/52))

When adding or editing a profile, the **Censorship mode** wizard offers:

- **Transport presets** — XHTTP+REALITY (`stream-one`), WebSocket/gRPC/HTTPUpgrade+TLS, plain TLS, mux for mobile operators.
- **uTLS fingerprint** — `firefox`, `edge`, `chrome`, `safari`, `random` (default: **firefox** when link has no `fp`).
- **RU sites direct** — routes `geosite:ru` / `geoip:ru` to direct outbound (requires geo assets from `scripts/fetch_cores.sh`).
- **Auto-detect** — suggests transport from subscription/link metadata.
- **ConfigEnhancer** — applies presets to generated xray/sing-box JSON without custom Xray forks.

Uses **official Xray-core** only — no unmaintained REALITY forks.

Docs: [censorship_resistance.md](../censorship_resistance.md)

### RioNexGate panel — optional MVP ([#51](https://github.com/RioTwWks/RioNexTunnel/pull/51))

Pair with a [RioNexGate](https://github.com/RioTwWks/RioNexGate) server for managed subscriptions and usage stats. **Fully opt-in** — manual links and third-party subscriptions work as before.

- **Settings → RioNexGate panel** — panel URL, register/login, manual refresh.
- **PanelManager** — REST client with timeouts, retries, `config_hash` diff, offline cache.
- **Stats upload** — bytes in/out queued on disconnect; replay when panel is back online.
- **Panel status card** — synced / stale / offline / error (no secrets in UI).

Panel device token is separate from VPN transport auth and SOCKS session credentials.

### Platform parity — Windows, macOS, Android, iOS ([#39](https://github.com/RioTwWks/RioNexTunnel/pull/39), [#41](https://github.com/RioTwWks/RioNexTunnel/pull/41))

| Platform | What's new |
|----------|------------|
| **Windows** | Desktop proxy plugin (`desktop_core.cpp`), WinINet/registry system proxy, core discovery in bundle `resources/` |
| **macOS** | Ports 1080/1081, credentials channel, HTTP system proxy parity |
| **Android** | `xray_available` probe, session creds in `start_with_json`, per-app split tunnel |
| **iOS** | PacketTunnel + Libbox API migration for sing-box 1.14, credentials channel, config persist/wipe |

Checklist: [platform_parity_checklist.md](../platform_parity_checklist.md)

## Platform notes

### Linux (reference — verified)

- Proxy mode with GNOME system proxy + browser extension helper.
- Kill switch Strict uses iptables (requires `CAP_NET_ADMIN` or root).
- Run `./scripts/fetch_cores.sh` before first connect.

### Windows

- Proxy mode: system HTTP proxy `127.0.0.1:1081`, SOCKS `127.0.0.1:1080` with session auth.
- **Browser helper not yet available** — use copy-credentials from Home/Settings (P3 backlog).

### macOS

- Same port layout as Linux; credentials visible in Settings while connected.
- Kill switch: proxy-mode fallback; full `pf` firewall rules not shipped.

### Android

- Full TUN VPN mode; split tunneling and kill switch at `VpnService` layer.
- Reconnect after changing split tunnel app list.

### iOS

- sing-box only (engine auto-select); PacketTunnel extension required.
- Per-app split tunneling **not available** (Network Extension limitation) — use routing presets instead.
- XHTTP+REALITY may be unsupported; prefer TCP+REALITY+Vision nodes from subscription.

## Known limitations & deferred items

| Item | Status | Notes |
|------|--------|-------|
| Kill switch **Adaptive** mode | Deferred | Per-app blocking; depends on split-tunnel + kill-switch integration |
| Windows **browser helper** | P3 | Linux has full native-messaging extension; Windows returns `false` in status |
| RioNexGate WebSocket commands | Not in MVP | `refresh_config`, `disconnect`, `switch_server` via long-poll/WS planned |
| RioNexGate periodic stats flush | Partial | Disconnect flush only; ~60s background timer not yet implemented |

| Protocol auto-fallback chain | Partial | Latency-based server pick exists; ordered transport fallback chain planned |

| Windows/macOS full OS firewall | Not shipped | WFP / `pf` integration for proxy-mode kill switch |

## Upgrade notes

1. **Desktop users:** run `./scripts/fetch_cores.sh` to update xray/sing-box and geo assets before connecting with RU direct or geo routing rules.
2. **Android split tunnel / kill switch:** reconnect VPN after changing settings.
3. **RioNexGate:** optional — skip panel setup if you use manual links or third-party subscriptions only.
4. **Security unchanged:** SOCKS remains on `127.0.0.1` with per-session password auth; credentials are wiped on disconnect.
